# Figures

These figures were generated by the scripts below. Benchmark values describe the
recorded runs; performance depends on hardware and dependencies.

## 1. `iapws95-benchmark.svg`

Regenerate: `HIP_VISIBLE_DEVICES=0 python figures/iapws95_benchmark.py`

IAPWS-95 property evaluation (ρ, h, cp, μ, k), this library's GPU-batched implementation vs. the reference iapws PyPI package (pure-Python, one state point at a time). Measured on an AMD Radeon RX 7800 XT (ROCm 7.2, torch 2.9.1) against `iapws` on the same machine's CPU, both libraries run at every batch size up to 20,000 points: speedup grows from 1.2× at 100 points to 59.9× at 20,000 points (both sides measured). Beyond that the pure-Python reference becomes impractical to run directly (an actual run at 1,000,000 points would take on the order of 45 minutes); extrapolating its measured per-point cost gives an estimated ~67× at 1,000,000 points, shown as a dashed line and explicitly labeled "extrapolated," not measured. Accuracy cross-checked against `iapws` at 300 random points, 280–800 K, 0.5–100 MPa: max relative error 0.038% (cp), <0.01% on the rest.

## 2. `iapws95-derivative-validation.svg`

Regenerate: `HIP_VISIBLE_DEVICES=0 python figures/iapws95_derivative_validation.py`

∂ρ/∂T|p from autograd (implicit function theorem, reattaching rho_Tp's detached Newton solve to T via F(ρ,T)=p(ρ,T)-ptarget=0) against an independent central finite-difference reference, p=25 MPa (supercritical), T from 300–800 K, 200 points, AMD Radeon RX 7800 XT / torch 2.9.1+rocm7.2.1. Mean relative error 5.4×10-5; the error rises to a measured maximum of 4.9×10-3 in a narrow band around the pseudo-critical temperature (~647 K) where ∂ρ/∂T is steep enough that the finite-difference reference itself, not the autograd derivative, loses precision.

## 3. `liquid-metal-uncertainty.svg`

Regenerate: `python figures/liquid_metal_uncertainty.py` (CPU; no GPU work involved —

Thermal conductivity vs. temperature for sodium, lead, and LBE (Sobolev 2020 correlations, `pinthac/properties/liqprops.py`), with a 95% Monte Carlo band (4,000 trials per temperature, `pinthac.uncertainty.perturb`) from each metal's documented model-form uncertainty (`uncert_k`). Sigma is linearly interpolated between each metal's stated low/high `uncert_k` bound across its valid temperature range — a stated modeling choice (see the script's docstring), not a value given directly by the source. At the top of each metal's valid range: Na 50.18 W/m-K [95% band 42.3, 58.1], Pb 23.49 W/m-K [16.6, 30.5], LBE 20.55 W/m-K [14.6, 26.9].

## 4. `sca-surrogate-validation.svg`

Regenerate: `HIP_VISIBLE_DEVICES=0 python figures/sca_surrogate_validation.py`

Rod DeepONet-PINN surrogate (checkpoint sca_rod_deeponet_best.pth, best validation loss 1.069e-4) vs. the ground-truth FVM solve (`pinthac.sca.rod.run_SCA_batch`), coolant temperature Ti and peak fuel temperature Tfuel,max, for three held-out operating points (never seen in training). Over 2,000 held-out runs: Ti MAE 0.113 K (0.018% mean relative), Tfuel,max MAE 5.03 K (0.356% mean relative). AMD Radeon RX 7800 XT for the surrogate forward pass.

## 5. `sca-inference-speed.svg`

Regenerate: `HIP_VISIBLE_DEVICES=0 python figures/sca_inference_speed.py`

Wall-clock cost of a full 100-node axial solve: the DeepONet surrogate against the iterative finite-volume solver it was trained on, both on an AMD Radeon RX 7800 XT (ROCm 7.2, torch 2.9.1). Plotted against batch size rather than as a single number, because the answer depends entirely on it: 2158× for a single-rod query (10 rods), 39× at 1,000, and 1.9× at 20,000. The iterative solver is itself vectorized over the batch, so its cost is nearly flat from 10 to 20,000 rods (4.1 to 5.0 s) while the surrogate's grows linearly — the surrogate wins overwhelmingly for the interactive, one-case-at-a-time queries a design study makes, and the advantage narrows toward break-even for the large sweeps the solver was already good at.
